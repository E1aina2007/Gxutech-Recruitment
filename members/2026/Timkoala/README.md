## AI 辅助记录

### 1. 我遇到的问题

在开发 [Golangchain](https://github.com/Timkoala/Golangchain) 时，我希望把项目从基础的 LLM 接口逐步扩展为包含多模型 Provider、Agent 工具调用、Prompt 模板、Memory、RAG 和并发批处理能力的轻量框架，同时尽量保持接口统一和零外部依赖。

这个过程中需要同时处理模块边界、接口兼容、并发安全、错误传播和文档一致性。随着功能增加，仅靠一次性手写所有实现很容易遗漏边界情况，因此我尝试使用 AI Coding 工具协助开发和审查。

### 2. 我是怎么向 AI 提问的

按模块拆分任务，并向它提供当前接口、目标行为和约束条件，让它协助生成实现思路、代码初稿和测试检查点。

例如，在扩展 Provider、Agent、Memory 与 RAG 等模块时，我会要求生成的实现保持现有接口风格、优先使用 Go 标准库，并考虑 `context` 取消、错误返回和并发访问等问题。生成代码后，再结合仓库中的其他模块检查命名、依赖和行为是否一致。

### 3. AI 的回答有没有直接解决？

AI 能较快给出模块骨架、重复性代码和常见实现方案，对补齐功能和发现潜在问题很有帮助，但生成结果不能直接视为最终实现。

尤其在并发控制、重试、接口兼容和资源释放方面，只看代码表面往往无法确认行为正确；文档中的示例也可能与实际接口不同步，因此仍需要人工审查和运行验证。

### 4. 如果没有，我后来怎么继续处理？

我会把 AI 生成的内容放回项目上下文中检查，通过编译、单元测试和实际调用验证行为，再根据结果调整接口与实现。对于并发和取消逻辑，则重点检查 goroutine 是否能够退出、错误是否正确返回、重试是否受控，以及 `context` 取消能否向下传递。

项目后续的提交中也持续进行了代码审计、单元测试补充、错误处理和并发安全优化，并同步更新 README，使文档描述与当前功能保持一致。这个过程让我形成了比较明确的 AI Coding 使用方式：让 AI 提高探索和实现速度，但由人负责约束、验证与最终取舍。
